## Chapter 7: Domain 3 (Continued): Fine-Tuning, Bedrock Agents & Model Evaluation — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Fine-tuning vs Continued pre-training: when to use each? | Fine-tuning: have labeled data, need specific task (classification, NER, sentiment). Continued pre-training: have unlabeled domain text, need vocabulary adaptation (medical, legal). Exam tip: unlabeled + domain = continued pre-training. Labeled + task = fine-tuning. |
| 2 | What are Bedrock Agent action groups? | Lambda functions that let Agents call external APIs. Example: check inventory API, call payment gateway. Exam tip: action groups = API calls. Knowledge Bases = document retrieval. Don't confuse them. |
| 3 | Bedrock Knowledge Bases: what data sources are supported? | S3, SharePoint, Confluence, Salesforce, web crawlers. Provides RAG (retrieval augmented generation) for Agents. Exam tip: Knowledge Bases ≠ action groups. KBs retrieve docs, action groups call APIs. |
| 4 | BLEU score range and what it measures? | 0-1 (higher = better). Measures n-gram overlap with reference text. Used for machine translation. Exam tip: BLEU = precision (exact matches). Common mistake: using BLEU for summarization (use ROUGE instead). |
| 5 | ROUGE score: what does it measure and what's it used for? | 0-1 (higher = better). Measures recall of n-grams from reference. Used for summarization quality. ROUGE-1 (unigrams), ROUGE-2 (bigrams), ROUGE-L (longest sequence). Exam tip: ROUGE = recall. BLEU = precision. |
| 6 | BERTScore range and what makes it different from BLEU/ROUGE? | 0-1 (higher = better). Uses embeddings to measure semantic similarity, not exact word matches. Best for paraphrase detection. Exam tip: BERTScore handles synonyms (cat/feline). BLEU/ROUGE require exact matches. |
| 7 | What are Bedrock Guardrails used for? | Content filters (hate speech, violence, sexual content), PII redaction (SSN, credit cards), denied topics (prevent discussing specific subjects), word filters. Exam tip: Guardrails = safety/compliance at inference time. |
| 8 | Fine-tuning minimum dataset size for reasonable results? | No hard minimum, but typically 500-1000 labeled examples for simple tasks, 5000-10000 for complex tasks. Exam tip: if scenario says 'only 50 labeled examples' → consider few-shot prompting instead of fine-tuning. |
| 9 | When should you use BLEU vs ROUGE vs BERTScore? | BLEU: machine translation (precision matters). ROUGE: summarization (recall matters—did we capture key points?). BERTScore: paraphrase quality (semantic similarity matters). Exam tip: translation=BLEU, summarization=ROUGE, paraphrase=BERTScore. |
| 10 | Can Bedrock Agents call multiple APIs in one workflow? | Yes. One Agent can have multiple action groups, each calling different APIs. Agent orchestrates multi-step tasks automatically. Exam tip: don't create multiple Agents when one Agent with multiple action groups works. |
| 11 | What data does continued pre-training require? | Large corpus of unlabeled text in the target domain (50GB+ typical). No labels needed. Adapts model vocabulary and understanding to domain (medical, legal, financial). Exam tip: rare use case—most problems solved with fine-tuning or RAG. |
| 12 | Do Bedrock Knowledge Bases require fine-tuning the model? | No. Knowledge Bases use RAG—retrieve documents at inference time, no model modification. Exam tip: RAG (Knowledge Bases) vs fine-tuning: RAG for frequently updated info, fine-tuning for task-specific behavior. |
